# Examples

Leanforge examples show both the input side and the user-owned result side of the workflow. They are
not generated applications and do not define product requirements for your project.

| Example | Shows |
|---|---|
| [Booking system](booking-system/README.md) | Intent elicitation, acceptance evidence, and first-run expectations for a small behavior-changing feature. |
| [Completed trusted-change package](trusted-change-package/README.md) | A sanitized real change with an approved contract summary, actual commit, verification evidence, remaining risk, and integration state. |

Use the booking example to see what a good Leanforge input looks like. Use the completed package to
see what should remain after Run, without mistaking internal workflow plumbing for the product result.
