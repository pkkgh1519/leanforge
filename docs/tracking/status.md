# 프로젝트 상태

## 검증된 현재 상태

- **v1.8.2 릴리스 기준:** v1.8.1 실행 의미와 orchestration을 유지하면서 README·CHANGELOG·canonical/generated manifest의 release version을 `1.8.2`로 맞췄다.
- **Release consistency guard:** build가 Git 없이 일곱 release surface의 정확한 label을 읽고 missing·ambiguous·mismatch를 거부한다. Baseline, 본문 예시 제외, 각 mutation을 focused 10개 test로 검증했다.
- **명시적 Run TDD 호출:** Codex canonical/generated metadata에 implicit invocation 금지가 일치한다.
- **Generated parity CI:** build 뒤 tracked drift, untracked output, 전체 unittest, whitespace를 순서대로 차단한다.
- **검증 상태:** 일반 환경에서 focused 10개와 전체 80개 test가 통과했고 반복 build의 generated bytes가 같았다. GNU Bash 3.2.57 환경에서도 build와 focused 10개 test가 통과했으며 generated drift가 없었다.
- **통합 상태:** v1.8.2 제품 변경은 PR #12로 main에 통합됐다. tag와 GitHub Release의 게시 여부는 GitHub 원격 상태를 기준으로 확인한다.

## 남은 확정 목표

1. **v1.9.0 semantic contract foundation:** route, failure precedence, lifecycle ownership, completion reuse, concern disposition, user output, load edge의 작은 machine-readable 계약과 별도 load graph를 만든다. Semantic event scenario, negative mutation suite, exact raw-byte baseline을 포함하되 전체 workflow DSL을 만들거나 footprint 감소를 완료 조건으로 삼지 않는다.
2. **v1.9.1 block-preserving split:** v1.9.0 계약이 확보된 뒤 core·worktree·parallel·external·failure overlay를 분리한다. Split 전후 의미, 재귀 load closure budget, 독립 행동 review를 통과해야 한다.

이 목표는 구체적인 다음 결과지만 현재 구현을 자동 승인하지 않는다. v1.9.1은 v1.9.0의 계약 증거 없이 선행할 수 없다.

## 미래 방향

- 실제 Claude Code·Codex host에서 별도 승인 후 20회 behavior smoke로 deterministic contract 외의 host 동작을 관찰한다.
- Token·latency 개선을 주장할 필요가 생길 때만 100회 반복 측정을 사용한다. 반복 측정은 deterministic gate를 대체하지 않는다.

## 차단 사항

현재 확인된 제품 blocker는 없다. 다음 확정 개발 목표는 v1.9.0 semantic contract foundation이며, 새 Prime delta에서 실행 범위를 승인한 뒤 시작한다.
